# Masroufi (مصروفي)

A bilingual personal finance app built with Flutter. Track daily expenses, set monthly budgets per category, follow a savings goal, and get spending insights, in English or Arabic, with light and dark themes.

## Features
- **Authentication:** Firebase Auth email/password login and registration with persistent sessions, and separate data for each user
- **Cloud sync:** all data is stored in Cloud Firestore, so it follows the user across devices
- **Offline-first caching:** the app opens instantly from a local cache, works with no connection, and uploads queued changes when back online
- **Dashboard:** monthly spend vs. budget, today and this week totals, a payday countdown, and recent transactions
- **Expenses:** add, view, and manage expenses with categories, plus a full transaction history
- **Budgets:** a monthly budget with a per-category breakdown and progress bars
- **Reports:** monthly summary (daily average, biggest expense, budget used), generated insights, and a 6M/12M spending trend
- **Savings goal:** progress tracker with an add-to-savings flow and an editable goal
- **Localization:** English and Arabic, with full right-to-left layout support
- **Theming:** light and dark modes
- **Currency:** configurable currency with locale-aware number formatting (Arabic and English numerals)
- **Responsive UI:** adaptive navigation for phones and larger screens, with desktop support

## Tech stack
- Flutter and Dart
- Provider for state management (one `ChangeNotifier` per feature, scoped per signed-in user)
- Firebase Auth for accounts
- Cloud Firestore for data, with its persistent offline cache
- SharedPreferences for user settings (theme, language, currency)
- Material Design

## Architecture
The project uses a feature-based structure: shared logic lives in `core/`, and each domain has its own folder under `features/`.

```
lib/
├── main.dart              # Startup: orientation, Firebase, Firestore cache, SharedPreferences, runApp
├── app.dart               # Global providers, MaterialApp, localization, theming, auth gate
├── user_scope.dart        # Per-user scoped state
├── firebase_options.dart  # Generated by `flutterfire configure`
│
├── core/                  # Shared foundation
│   ├── settings/          # Settings provider (theme, language, currency)
│   ├── firebase/          # Collection names, cache settings, sync status
│   ├── theme/             # Light and dark themes
│   ├── l10n/              # Localization and translated strings (English/Arabic)
│   ├── currency/          # Currency definitions and formatting
│   └── utils/             # Helpers and formatting utilities
│
└── features/              # One folder per domain
    ├── auth/              # Login, registration, auth provider and repository
    ├── home/              # Main shell and adaptive navigation
    ├── expenses/          # Add, view, and manage expenses
    ├── categories/        # Expense categories
    ├── budget/            # Budget screens and calculations
    ├── reports/           # Charts, summaries, insights
    ├── savings/           # Savings goal tracking
    └── settings/          # Preferences UI

test/
├── settings_test.dart     # Settings, parsing, translations, currency
└── firestore_test.dart    # Repositories, seeding, provider caching
```

Platform folders (`android/`, `ios/`, `web/`, `windows/`, `linux/`, `macos/`) are the standard Flutter targets. Firebase does not support Linux desktop, so the Linux build no longer runs.

### Data model (Firestore)
Every document lives under the signed-in user, so the security rules in [`firestore.rules`](firestore.rules) only need to check "is this the owner?".

```
users/{uid}                    name, email, defaultCurrency, monthlyIncome, paydayDay, createdAt
├── expenses/{id}              title, merchant, amount, expenseDate, categoryId, category{...}, paymentMethod
├── budgets/{overall|category} amount, categoryId, category{...}, period, order
├── savingsGoals/{id}          name, targetAmount, currentAmount, monthlyContribution, jarCharacter
└── categories/{id}            custom categories (the six defaults live in code)
```

Firestore has no JOIN, so expenses and budgets keep a small copy of their category (name, icon, color) and a list can be drawn in one read.

### State management and caching
- **Providers.** `app.dart` provides `SettingsProvider` and `AuthProvider` app-wide. Once someone signs in, `UserScope` creates `CategoryProvider`, `ExpenseProvider`, `BudgetProvider` and `SavingsProvider` for that user only, keyed by their uid. Logging out throws them away.
- **Streams instead of reloads.** Each provider subscribes to a Firestore `snapshots()` stream. Adding, editing or deleting just writes, and the change comes back through the stream (also when it is made on another device).
- **Persistent cache.** `FirestoreCache.configure` turns on Firestore's on-disk cache (100 MB). The first snapshot is served from the cache, so screens fill instantly and the app works offline.
- **Offline writes.** Writes are applied to the cache at once and sent in the background (`sendInBackground`), so the UI never waits for the network. Queued writes upload when the connection returns.
- **In-memory cache.** Providers keep the latest data, and `ExpenseProvider` memoizes monthly totals until the list changes.
- **Sync status.** The dashboard shows "Offline · showing saved data" or "Syncing changes…" based on the snapshot metadata.

## Testing
`test/settings_test.dart` covers:
- parsing numeric input in Arabic and English formats
- persisting theme, language, and currency
- translation correctness
- currency formatting rules

`test/firestore_test.dart` runs against an in-memory Firestore ([fake_cloud_firestore](https://pub.dev/packages/fake_cloud_firestore)) and covers:
- seeding a new account (profile, split budgets, savings jar)
- adding, ordering, updating and deleting expenses, scoped per user
- atomic savings contributions (`FieldValue.increment`)
- the provider's cached month totals refreshing when new data arrives

```bash
flutter test
```

## Getting started
**Prerequisites:** the [Flutter SDK](https://docs.flutter.dev/get-started/install), an emulator or physical device, and a [Firebase](https://console.firebase.google.com) project.

```bash
git clone https://github.com/IbrahiimHassan/Masroufi.git
cd Masroufi
flutter pub get
```

### Firebase setup
1. In the [Firebase console](https://console.firebase.google.com), create a project.
2. **Authentication → Sign-in method:** enable **Email/Password**.
3. **Firestore Database:** create a database, then paste the contents of [`firestore.rules`](firestore.rules) into the **Rules** tab and publish.
4. Link the app to the project. This overwrites the placeholder `lib/firebase_options.dart` and adds the platform config files:
   ```bash
   npm install -g firebase-tools        # once
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
5. Run the app:
   ```bash
   flutter run
   ```
